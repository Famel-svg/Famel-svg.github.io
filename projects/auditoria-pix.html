o problemathe problem

A Resolução BCB nº 1/2020 e a LGPD pedem rastreabilidade de cada operação Pix: quem executou, quando, de onde, e como os dados estavam antes. Um log de texto registra que algo aconteceu, mas não mostra o que mudou. Este projeto separa as duas coisas: o AOP registra o contexto e o Envers registra o estado da entidade a cada revisão.BCB Resolution 1/2020 and the LGPD require traceability of every Pix operation: who ran it, when, from where, and what the data looked like before. A text log records that something happened but not what changed. This project splits the two concerns: AOP records the context and Envers records the entity state at each revision.

O contexto é capturadoThe context is captured

AuditLogService.registrar lê o usuário do SecurityContext, o IP e a URI da requisição, e grava em audit_log numa transação própria (REQUIRES_NEW). Por isso o registro persiste mesmo se a operação de negócio sofrer rollback.AuditLogService.registrar reads the user from the SecurityContext, the IP and the request URI, and writes to audit_log in its own transaction (REQUIRES_NEW). That is why the record persists even if the business operation rolls back.

Ao salvar, o Hibernate grava pix_transferencia. Because PixTransferencia is @Audited, Envers writes the full state to pix_transferencia_aud and the revision number to REVINFO.

src/main/java/br/com/pixauditoria/aspect/AuditAspect.java
@Aspect
@Component
@Order(1)
public class AuditAspect {

    private final AuditLogService auditLogService;

    public AuditAspect(AuditLogService auditLogService) {
        this.auditLogService = auditLogService;
    }

    @Around("execution(* br.com.pixauditoria.service.PixService.*(..))")
    public Object interceptar(ProceedingJoinPoint joinPoint) throws Throwable {
        String metodo = joinPoint.getSignature().getName();
        try {
            return joinPoint.proceed();
        } finally {
            auditLogService.registrar(metodo); // ← delega para o service
        }
    }
}

O aspecto só delega para AuditLogService. A regra de auditoria fica fora de PixService, então o código de negócio não depende dela.The aspect only delegates to AuditLogService. The audit rule stays out of PixService, so the business code does not depend on it.

src/main/java/br/com/pixauditoria/service/AuditLogService.java
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void registrar(String metodo) {
        try {
            String usuario = Optional.ofNullable(SecurityContextHolder.getContext().getAuthentication())
                    .map(Authentication::getName)
                    .orElse("ANONIMO");

            RequestAttributes attrs = RequestContextHolder.getRequestAttributes();

            String ip = "N/A";
            String endpoint = "N/A";

            if (attrs instanceof ServletRequestAttributes servletAttrs) {
                HttpServletRequest request = servletAttrs.getRequest();
                ip = request.getRemoteAddr();
                endpoint = request.getRequestURI();
            }

            auditLogRepository.save(new AuditLog(usuario, ip, metodo, endpoint, "PixTransferencia"));

        } catch (Exception e) {
            // Falha silenciosa — log nunca deve quebrar o fluxo de negócio
            System.err.println("Falha ao salvar log de auditoria: " + e.getMessage());
        }
    }

O finally registra cada operação do serviço, mesmo quando ela falha, com a origem (usuário, IP, endpoint) gravada em audit_log. REQUIRES_NEW usa transação própria, então o registro sobrevive a um rollback da operação. O catch mantém a operação de negócio de pé mesmo se a auditoria falhar.The finally block records each service operation, even when it fails, with its origin (user, IP, endpoint) written to audit_log. REQUIRES_NEW uses its own transaction, so the record survives a rollback of the operation. The catch keeps the business operation running even if the audit write fails.

src/main/java/br/com/pixauditoria/service/PixService.java
    @Transactional(readOnly = true)
    public List<AuditLogResponse> buscarHistorico(UUID id) {
        pixRepository.findById(id).orElseThrow(() -> new TransferenciaNaoEncontradaException(id));

        AuditReader auditReader = AuditReaderFactory.get(entityManager);
        List<Number> revisions = auditReader.getRevisions(PixTransferencia.class, id);

        return revisions.stream().map(rev -> {
            PixTransferencia versao = auditReader.find(PixTransferencia.class, id, rev);
            return new AuditLogResponse(
                    "SYSTEM",
                    "N/A",
                    "ENVERS_REVISION",
                    "/historico",
                    String.valueOf(rev),
                    versao.getStatus().toString()
            );
        }).toList();
    }

O histórico usa AuditReader sobre o EntityManager e lista cada revisão com o seu status. O estado completo de cada versão fica guardado em _aud, pronto para comparação.History uses AuditReader over the EntityManager and lists each revision with its status. The full state of each version is kept in _aud, ready for comparison.
