Login gera o JWTLogin issues the JWT

O app chama POST /api/auth/login. O AuthService confere a senha com o hash BCrypt guardado na coleção users do Firestore e devolve um JWT assinado em HS256, válido por 8 horas por padrão.The app calls POST /api/auth/login. AuthService checks the password against the BCrypt hash stored in the users collection in Firestore and returns a JWT signed with HS256, valid for 8 hours by default.

Tempo real via STOMPReal time via STOMP

Cada mensagem é publicada em /topic/conversation/{id} pelo broker STOMP. Subscribed web clients receive it instantly, and clients sending through /app/chat.send follow the same path.

Push para quem está foraPush for people outside the app

Para cada participante que não é o remetente e tem fcmToken, o PushNotificationService envia uma mensagem FCM com título, prévia de até 120 caracteres e os dados da conversa. No celular, WtcFirebaseMessagingService mostra a notificação.For each participant who is not the sender and has an fcmToken, PushNotificationService sends an FCM message with a title, a preview of up to 120 characters and the conversation data. On the phone, WtcFirebaseMessagingService shows the notification.

@Configuration
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void configureMessageBroker(MessageBrokerRegistry config) {
        config.enableSimpleBroker("/topic");
        config.setApplicationDestinationPrefixes("/app");
    }

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws/chat").setAllowedOriginPatterns("*").withSockJS();
        // WebSocket nativo (Android/iOS) — sem SockJS
        registry.addEndpoint("/ws/native").setAllowedOriginPatterns("*");
    }
}

Configura o broker em memória (/topic), o prefixo de aplicação (/app) e dois endpoints: /ws/chat com SockJS para navegadores e /ws/native para WebSocket nativo.Configures the in-memory broker (/topic), the application prefix (/app) and two endpoints: /ws/chat with SockJS for browsers and /ws/native for native WebSocket.

wtc-crm-backend/src/main/java/br/com/fiap/wtccrm/auth/security/JwtAuthenticationFilter.java
@Override
protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain chain)
        throws ServletException, IOException {
    String authHeader = request.getHeader("Authorization");
    if (authHeader != null && authHeader.startsWith("Bearer ")) {
        String token = authHeader.substring(7);
        if (jwtUtil.validateToken(token)) {
            String userId = jwtUtil.extractUserId(token);
            String role = jwtUtil.extractRole(token);
            var auth = new UsernamePasswordAuthenticationToken(
                    userId,
                    null,
                    List.of(new SimpleGrantedAuthority("ROLE_" + role)));
            auth.setDetails(new WebAuthenticationDetailsSource().buildDetails(request));
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
    }
    chain.doFilter(request, response);
}

O JwtAuthenticationFilter lê o Bearer do cabeçalho Authorization, valida o token com o JwtUtil e preenche o SecurityContext com a role do usuário (ROLE_OPERATOR ou ROLE_CLIENT).JwtAuthenticationFilter reads the Bearer token from the Authorization header, validates it with JwtUtil and fills the SecurityContext with the user's role (ROLE_OPERATOR or ROLE_CLIENT).

fun sendMessage(text: String) {
    val cid = conversationId ?: return
    if (text.isBlank()) return

    val session = SessionManager.session ?: return

    viewModelScope.launch {
        try {
            val auth = "Bearer ${session.token}"
            val request = ChatMessageDTO(
                conversationId = cid,
                senderId = session.userId,
                senderName = session.name,
                content = text,
                type = "TEXT",
                mediaUrl = null,
                status = null,
                sentAt = null
            )

            withContext(Dispatchers.IO) {
                RetrofitInstance.api.sendMessage(auth, cid, request)
            }
        } catch (e: Exception) {
            Log.e("ChatViewModel", "Falha ao enviar mensagem via REST", e)
        }
    }
}

O ChatViewModel envia mensagens por REST (sendMessage) e mantém um listener em tempo real sobre chats/{id} no Realtime Database (connectFirebaseChatListener).ChatViewModel sends messages over REST (sendMessage) and keeps a real-time listener on chats/{id} in the Realtime Database (connectFirebaseChatListener).
