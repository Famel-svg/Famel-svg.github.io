Estoque Reserva

Duas pessoas, uma unidade: só uma reserva passa.Two people, one unit: only one reservation gets through.

o problemathe problem

Dois clientes leem estoque = 1 ao mesmo tempo. Sem controle, os dois decrementam e as duas reservas são aceitas: overbooking. O banco precisa decidir quem perde.Two customers read stock = 1 at the same time. Without a guard, both decrement and both reservations are accepted: overbooking. The database has to decide who loses.

Raio-XX-ray

Threads disputam a mesma linha. A primeira atualização feita com a versão lida vence; as outras veem a versão mudar e recebem 409.Threads compete for the same row. The first update made with the version it read wins; the others see the version change and get 409.

No teste, 50 threads chamam reservar() para o mesmo produto, com estoque 1. Um CountDownLatch libera todas ao mesmo tempo.In the test, 50 threads call reservar() for the same product, with stock 1. A CountDownLatch releases them all at once.

src/main/java/com/estoque/reserva/produto/Produto.java
@Entity
@Table(name = "produto")
public class Produto {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 120)
    private String nome;

    @Column(name = "estoque_disponivel", nullable = false)
    private int estoqueDisponivel;

    @Version
    private long version;

    // ...

    public void reservar(int quantidade) {
        if (quantidade <= 0) {
            throw new IllegalArgumentException("quantidade deve ser positiva");
        }
        if (quantidade > estoqueDisponivel) {
            throw new EstoqueInsuficienteException(
                    "estoque insuficiente para " + nome + ": disponível " + estoqueDisponivel);
        }
        estoqueDisponivel -= quantidade;
    }

Sem @Version, duas transações leriam estoque = 1 e gravariam estoque = 0 sem nenhum erro. Com ele, cada UPDATE carrega a versão lida, e a segunda escrita falha.Without @Version, two transactions could read stock = 1 and both write stock = 0 with no error. With it, each UPDATE carries the version it read, and the second write fails.

src/main/java/com/estoque/reserva/api/TratadorDeErros.java
    @ExceptionHandler({EstoqueInsuficienteException.class, OperacaoInvalidaException.class})
    public ProblemDetail regraDeNegocio(RuntimeException e) {
        return problema(HttpStatus.CONFLICT, e.getMessage());
    }

    /** Conflito de @Version: outra transação alterou o produto primeiro. */
    @ExceptionHandler({OptimisticLockingFailureException.class, OptimisticLockException.class})
    public ProblemDetail conflitoDeVersao() {
        return problema(HttpStatus.CONFLICT, "estoque alterado por outra requisição; tente novamente");
    }

Estoque insuficiente e conflito de versão caem no 409. A mensagem do conflito pede nova tentativa ao cliente.Insufficient stock and version conflicts both return 409. The conflict message asks the client to try again.
